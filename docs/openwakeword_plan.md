# План: собственная модель openWakeWord для русской фразы «хей луна»

Статус: этап 0 выполнен технически (окружение, синтез, QC), этапы 1–9
не начаты. Итоги — `wake_model/README.md`; прослушивание синтеза остаётся
за пользователем.

Цель: заменить Vosk как wake-движок там, где он слаб — 1,5–3 м и фон
(музыка/ТВ). Vosk остаётся движком STT для команд и запасным
(`wake_engine: "vosk"`).

---

## 0. Цель и критерии приёмки

| Метрика | Цель | Сейчас Vosk (датасет A) |
|---|---|---|
| FRR ≤ 1 м, тишина | ≤ 5 % | 0 % |
| FRR 1,5–2 м + музыка/ТВ | ≤ 20 % | 60–75 % |
| FAR на реальных негативах | ≤ 5 % | 7 % |
| FAR на фоне | ≤ 0,5 срабатывания/час | не измерялось |
| CPU | ≤ 5 % одного ядра (замерим сами) | — |
| Размер модели | 1–2 МБ onnx | ~87 МБ у Vosk |

Решение о замене принимается по реальным записям, а не по синтетике.
Если цель после этапа 7 не достигнута — разбираемся, что дало бы улучшение:
записи, аугментации или объём негативов; Vosk пока продолжает работать.

---

## 1. Принцип: обучаем на синтетике, проверяем на реальных

Официальная разработка openWakeWord рассчитана на синтетику: минимум
несколько тысяч позитивов и десятки часов негативов; встроенные модели
обучались вообще на 100 % синтетического TTS. Реальных записей всегда
мало, и они легко «переучивают» модель на один голос. Поэтому роли такие:

- **Training-позитивы** — Piper TTS, 10–20 русских голосов, 3–10 тыс. клипов.
- **Реальные записи** (3–5 человек, 300–500 дублей) — validation/test,
  максимум 5–10 % в train.
- **Негативы** — наши фоновые записи + публичные корпуса, 20–50 часов.

## 2. Этапы

### Этап 0. Окружение (0,5 дня, я)

- Папка `wake_model/` в проекте: `data/`, `features/`, `config.yaml`,
  `checkpoints/`, обучающие скрипты.
- Отдельный учебный venv (torch не тянем в рабочий venv ассистента):
  `torch`, `torchinfo`, `torchmetrics`; `openwakeword==0.6.0` уже стоит.
- Piper: бинарник из релизов rhasspy/piper + голоса `ru_RU`
  (ruslan, denis, dmitri, egor, ilya, irina, maxim и др., ~60 МБ каждый).
- Проверка: сгенерировать 100 клипов, прослушать 20 вручную.

### Этап 1. Синтетические позитивы — Piper (0,5–1 день, я)

- Фраза «хей луна» (основная); «эй луна» — решить на этапе 7, нужна ли
  отдельная модель или сработает основная.
- Вариации Piper: `length_scale` 0,75–1,3, `noise_scale`/`noise_w`,
  пауза между «хей» и «луна» 0–300 мс — и слитно, и раздельно.
- 10–20 голосов по 200–300 клипов → 3–10 тыс. всего.
- Формат: 16 кГц, моно, 16 бит; lead/tail паузы 0,3–0,5 с, обрезка к речи.
- Ручной QC: выборочно слушать, выбрасывать клипы с артефактами.
  Брак Piper («хей» как «хэ», глотание «й») — главный риск этапа.

### Этап 2. Реальные позитивы (2–3 сессии по 30–40 мин, вы)

- 3–5 человек, обязательно хотя бы одна женщина; по 60–100 дублей на
  голос → 300–500 клипов.
- Условия: 0,6 / 1 / 1,5 / 2 м; тишина / музыка / ТВ; обычный и тихий голос.
- Тот же ноутбук и микрофон, что в датасете A.
- Метаданные: спикер, дистанция, условие, уровень, файл.
- Инструмент в духе `record_dataset` с проверкой дублей
  (прослушать → принять/перезаписать), чтобы не портить принятые файлы.

### Этап 3. Негативы (неделя пассивной записи + 1 день корпусов, вы/я)

Реальная запись — тем же микрофоном, что датасет A:
- ТВ — 10 ч, музыка — 10 ч, бытовая речь/разговоры — 5 ч,
  улица/окно — 5 ч, вентилятор — 5 ч. Итого 20–50 ч.
- Ночной цикл: ноутбук пишет 5–10-минутные чанки, 16 кГц моно,
  метаданные: источник, дата, помещение. Нужен скрипт в стиле
  `record_dataset --background`.

Публичные корпуса (скачиваю я):
- Common Voice ru (CC0) — подвыборка 5–10 ч разговорной речи.
- MUSAN — музыка/шум/речь для аугментаций.
- OpenSLR SLR-109 (Golos) — запас русской речи.
- DiPCo (Amazon) — ~5,5 ч far-field офисного фона, самый реалистичный
  пул для проверки FAR.
- **Добыча жёстких негативов из корпусов:** прогнать речь через Vosk
  с wake-грамматикой и отобрать клипы, где он слышит «луна»/«эй»/«хей», —
  это самые опасные примеры для новой модели.

### Этап 4. Аугментации (я, 1 день)

- RIR из OpenSLR SLR-26/28 (реверберация комнат), случайное применение.
- Шум: MUSAN noise + наши фоновые записи, SNR 0–15 дБ, громкость ±10 дБ.
- Скорость 0,8–1,2, лёгкий pitch shift (5–10 % клипов), вставки пауз.
- Всё только над TRAIN; val/test — чистые реальные записи.

### Этап 5. Датасет и разбиение (я, 0,5 дня)

```
wake_model/data/positive/{synthetic,real}
wake_model/data/negative/{speech,music,tv,street,hard}
wake_model/data/rir
wake_model/features   # memmap фич, ~4–5 ГБ
wake_model/checkpoints
```

- Манифест-CSV: путь, источник, спикер, дистанция, условие, длина.
- Разбиение: **speaker-disjoint** (спикер из test никогда не в train),
  **session-disjoint** для фона (часть часов только для test).
- Жёсткие негативы — в val и test.

### Этап 6. Фичи и обучение (я)

- Фичи: `openwakeword.utils.compute_features_from_generator`
  (melspectrogram ONNX + frozen Google-embedding), memmap на диск,
  считать заранее по ночам.
- Три прогона (YAML-конфиги):
  - A: DNN, layer_dim 128, «хей луна»;
  - B: DNN 256, больше аугментаций;
  - C: RNN 128, 2 слоя.
- Batch 64, lr 3e-4 → 1e-4, 50–100k шагов, ранняя остановка по val.
- Внутренняя метрика: val FRR при фиксированном FAR.
- Обучение: Colab (GPU, 1–2 ч на прогон) или локальный CPU (ночь на
  прогон — для маленькой головы реально).

### Этап 7. Оценка и порог (я, 1 день)

1. Быстрая оценка протоколом `wake_eval` в режиме `--engine openwakeword`
   на датасете A: FRR/FAR по блокам, условиям и дистанциям.
2. FRR на held-out реальных дублях (этап 2), плюс реверберация/шум.
3. FAR на часах фона, не участвовавших в обучении; сюда же DiPCo.
4. Кривая FRR при фиксированном FAR; порог выбирается на val
   (обычно 0,3–0,6) и подтверждается на test; пишем его в config.json.
5. Проверка «эй луна»: срабатывает ли основная модель; если нет —
   вторая модель или отдельный порог.

### Этап 8. Экспорт и интеграция (я, 0,5 дня)

- `export_to_onnx` → `%LOCALAPPDATA%\VoiceAssistant\models\openwakeword\hey_luna_ru.onnx`.
- `config.json`: `wake_engine: "openwakeword"`, `wake_model`,
  `wake_threshold` — переключение движка через обычные настройки.
- A/B против Vosk: тот же датасет A + ночной тест на фоне; логируем
  срабатывания обеих моделей на одних файлах и сверяем.
- `doctor.py --wake` продолжает работать (поддержка двух движков уже есть).

### Этап 9. Эксплуатация и итерации (оба, постоянно)

- Переключатель в config: сохранять аудио вокруг false-positive и
  false-negative (невеликий кольцевой буфер, чтобы вес был мал) —
  материал для дообучения.
- Раз в квартал: разобрать логи, собрать новые сложные примеры,
  докачать негативы, дообучить.
- Регрессионный тест при каждом изменении: датасет A + фоновый пул.

## 3. Риски и как их отслеживать

| Риск | Признак | Митигация |
|---|---|---|
| Плохая русская синтетика | клипы звучат как «хэ луна» | QC на этапе 1, больше голосов, другой TTS |
| Переобучение на голос | val хуже train, особенно на новых голосах | speaker-disjoint, синтетика в основе |
| FAR на фоне не проверен | пропущенный пул негативных часов | этап 3 стартует раньше этапа 6 |
| Фраза из двух слов с паузой | модель ловит только слитно | генерировать и слитно, и с паузой |
| Лимиты Colab | прогон обрывается | чекпоинты на Google Drive; CPU как запасной |
| Расчёт фич на CPU | долго | считать заранее на диске, ночными задачами |
