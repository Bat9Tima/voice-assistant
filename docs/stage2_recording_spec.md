# ТЗ: запись реальных позитивов «хей луна» (этап 2)

Статус: проект ТЗ. Реализация инструмента и сессии записи — только после
явного разрешения владельца проекта.

## 1. Цель и объём

Собрать реальные дубли «хей луна» на два микрофона:

- `laptop` — боевой микрофон ассистента (тот же ноутбук, то же место);
  основа train/val/test, данные максимально близки к эксплуатации;
- `studio` — отдельный качественный микрофон; чистый контрольный набор
  и проверка cross-mic робастности.

| Параметр | Значение |
|---|---|
| Дикторы | 3–5, минимум одна женщина; короткие id (`anna`, `tim`, …) |
| Дубли на диктора | 60–100 на каждый микрофон |
| Дистанции | 0,5 / 1 / 1,5 / 2 м (коды `05/10/15/20`) |
| Фон | тишина / музыка / ТВ (`quiet/music/tv`) |
| Уровень голоса | обычный / тихий (`norm/sub`) |
| Матрица ячеек | 4 × 3 × 2 = 24 |
| Дублей на ячейку | 2–3 |
| Итого на диктора × микрофон | ≈ 72–100 |
| Итого на этап (два микрофона) | ≈ 450–1000 клипов |

Опционально (время есть, дёшево): отдельный блок фразы «эй луна» по
сокращённой матрице (тишина × дистанции × обычный голос), с пометкой в
manifest — решение о его использовании принимается на этапе 7.

## 2. Схема сессии

Один прогон = один диктор × один микрофон (30–40 минут).

```
setup: устройство → калибровка фона 5 с → пилотный дубль (уровень)
  │
  ▼
цикл: фон как внешний блок [тишина → музыка → ТВ]
      внутри блока порядок (дистанция × уровень) перемешан (seed)
      дистанция × условие × уровень = 24 ячейки
      │
      ├─ отсчёт 2 с + звуковой маркер (маркер вне записи)
      ├─ запись 3,0 с (нативный формат микрофона → raw/)
      ├─ плейбек → [1] принять / [2] переснять / [3] брак+комментарий
      │      └─ автоподсказки: тихо/громко/клиппинг/длительность/ASR
      ├─ принят → pending + запись в журнал (accepted не перезаписываются)
      ▼
finalize: 16 кГц моно → обрезка+пад 0,3/0,3 → метрики → GigaAM QC
  │
  ▼
manifest.csv + listen-страница → вердикт на слух → exclude.txt
```

Рандомизация: смена фона дорога (включать/выключать ТВ), поэтому фон —
внешний блок; порядок внутри блока фиксированно-случайный, у разных
дикторов порядок разный. Наушники — только у студийного канала; боевой
пишется с динамиками, как в эксплуатации; маркер старта звучит до окна
записи и в файл не попадает.

## 3. Инструмент записи — `wake_model/scripts/record_positives.py`

Запуск (эскиз интерфейса, без реализации):

```
--list-devices                показать входы и их частоты
--setup                       сессия: диктор, микрофон, калибровка
--resume                      продолжить прерванную сессию по журналу
--review <путь>               плейбек принятых, брак/комментарии
--finalize                    ресемпл, обрезка, QC, manifest, страница
```

### 3.1 Настройка сессии

- Выбор входного устройства (id/имя), отображение фактической частоты.
- Пилотный дубль + подсказка по уровню: пик вне −18…−3 dBFS → «тихо/
  громко», клиппинг → «отодвинуться от микрофона».
- Калибровка: 5 с фона, noise floor сохраняется в manifest сессии.

### 3.2 Цикл записи (ядро)

- Отсчёт 2 с + маркер; окно записи 3,0 с, фиксированное.
- Плейбек сразу; между дублями — только ожидание человека.
- Действия: принять / переснять / брак с комментарием / повтор плейбека /
  пауза-выход. **Принятые файлы никогда не перезаписываются**: пересдача
  получает следующий `take`, бракованные остаются на диске с пометкой
  (в manifest не попадают) — так принятые данные не портятся.
- Каждый дубль: WAV в `pending/` + строка в журнале сессии.

### 3.3 Автоподсказки (не блокируют приём)

- пик < −18 dBFS → «тихо»; > −1 dBFS или клиппинг → «громко»;
- длительность речи вне 0,7–2,5 с → «проверить темп/дистанцию»;
- хеш PCM совпал с уже принятым дублем → «точный повтор»;
- Vosk слышит «луна»/«хей» не того вида → «переснять?» — только
  предупреждение: ASR ошибается и на реальной речи, окончательное
  решение за человеком (принцип «верим ушам, а не ASR»).

### 3.4 Журнал и восстановление

`session.json`: диктор, микрофон, прогресс по ячейкам, статусы дублей,
комментарии. Выход/сбой → `--resume` продолжает с того же места.

## 4. Формат файлов и метаданные

- Имена: `{speaker}_{mic}_{dist}_{cond}_{level}_{take:03d}.wav`,
  например `anna_laptop_d10_music_norm_003.wav`.
- `raw/` — нативная запись микрофона (без конвертации, для перепайпа);
  `processed/` — 16 кГц, моно, int16, обрезка по энергии (порог −40 dBFS,
  паддинг 0,3/0,3 с — как у синтетики), дедуп по md5 PCM-фреймов.
- `wake_model/data/positives_real/manifest.csv`, разделитель «;»:

```
file;speaker;mic;distance_m;condition;level;phrase;take;
duration_s;peak_db;rms_db;clipping;noise_floor_db;
has_luna;has_hey;exact;text;timestamp;notes;kept
```

Схема совместима по смыслу с `positives_tts/manifest.csv`: этап 5
соберёт оба каталога одним механизмом.

## 5. Финализация и QC

1. Ресемпл `raw` → 16 кГц, обрезка+паддинг (та же логика, что у
   `synthesize_silero.py`: `trim_speech` + lead/tail).
2. `check_qc.py` по processed: длительность/пик/клиппинг + GigaAM →
   `exact`-флаг только как статистика; **авто-брак реальных записей
   запрещён** — приемка только человеком (на слух через страницы).
3. Сборка manifest + listen-страница (выборочно: 2–3 клипа на ячейку и
   на диктора) → решения по exclude.txt.

## 6. Приватность и ресурсы

- Всё локально, без облачных сервисов; участники предупреждены, что
  голос пойдёт в локальную обучающую выборку личного ассистента.
- Данные в `wake_model/data/positives_real/` (gitignore).
- Зависимости: sounddevice и scipy уже в окружениях проекта; GigaAM-QC —
  существующий wake_model-venv. Новых тяжёлых пакетов нет.

## 7. Пилот и критерии готовности

- Пилот: 20 дублей на самом себе (оба микрофона, 2–3 ячейки) →
  проверить уровни, имена, журнал, manifest; после этого внешние дикторы.
- Этап готов, когда: ≥3 диктора × ≥60 дублей × 2 микрофона; каждая
  ячейка матрицы закрыта ≥2 дублями; manifest собран; QC-отчёты и
  страницы прослушивания готовы.

## 8. Связь с этапом 5 (разбиение)

- Speaker-disjoint: дикторы из test никогда не в train.
- Микрофоны не смешивать в метрике: FRR/FAR отдельно laptop и studio.
- Часть дублей музыки/ТВ держать только для test.
