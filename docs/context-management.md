# Управление контекстом диалога

Состояние на 17.11.2026, ветка `feature/dialog-mode`.

## Что сделано

- `f200f9c` — `ContextBuilder` (`app/context_builder.py`): единая сборка
  системного промпта и сообщений, бюджет в токенах и обрезка по
  приоритетам.
- `f8b9d98` — скользящее резюме текущего разговора
  (`app/rolling_summary.py`): реплики, выпавшие из окна истории,
  сжимаются фоновым запросом и попадают в следующий ход отдельным блоком.

### Резюме сессии v2

`app/summary_schema.py` и `SUMMARY_PROMPT_VERSION = 2`: модель возвращает
JSON с полями `facts`, `decisions`, `unfinished`, `topics`, `summary`.
У каждого пункта первых трёх списков есть `evidence` — дословная цитата
пользователя. Пункт без подтверждения отбрасывается при разборе, поэтому
в память не попадают догадки модели и слова Луны. Структура целиком
лежит в `summaries.data`, а в `summaries.summary` — обычный текст для
эмбеддинга и чтения. Старые записи без колонки `data` мигрируют в `{}`.

Транскрипт для резюме режется с двух сторон: 40% лимита остаётся началу
разговора, остальное — хвосту. Раньше начало терялось, вместе с фактами,
которые пользователь сообщил первыми.

### Дневной дайджест памяти

К семантическим находкам перед ними добавляются сегодняшние завершённые
сессии с числом реплик не меньше `memory.digest_min_messages` (6), не
больше `digest_limit` (3) штук. Каждое резюме сжимается до
`digest_item_chars` (320) символов. Это страховка от чистого поиска:
мета-вопрос «что мы обсуждали» плохо совпадает с длинным резюме, хотя
свежая сессия важна сама по себе. Повторы с семантическими хитами
убираются по `session_id`, общий лимит блока — `memory.max_chars` (2400).

Порядок блоков: правила, дата и время, профиль пользователя, факты Луны,
краткое содержание текущего разговора, память, окно истории. Правила и
текущая реплика не режутся никогда. При переполнении бюджета первыми
уходят память, содержание разговора, факты личности, профиль и самые
старые реплики истории.

Бюджет: `dialog.context.budget_tokens` (6000), `chars_per_token` (2.5),
`0` отключает. Оценка приблизительная, по символам: точный токенизатор
под конкретную модель не используется. Факт обрезки пишется в лог на
`INFO`, размер контекста — на `DEBUG`.

Окно истории хранится в `SessionMemory` и задаётся
`history_messages` (12) и `history_chars` (4000). `window_start()`
возвращает индекс первой реплики окна: всё до него отдаётся
`RollingSummary`. Резюме живёт только в памяти, сбрасывается на входе и
выходе из диалога, ошибка модели оставляет прошлое содержание.

## Что сознательно не сделано

- **Дедуп памяти против текущего разговора.** Память содержит только
  прошлые сессии, поэтому текущей истории там быть не может. `top_k`
  уже 3 (в оговорённом диапазоне 2–3). Нечёткий фильтр на таких данных
  ничего не отсекает, зато может выкинуть уместное воспоминание. Точный
  дедуп по `session_id` есть в дневном дайджесте.
- **Умный отбор контекста LLM-вызовом на каждый ход.** Даёт задержку в
  голосовом цикле и лишние ошибки, а на нынешних объёмах не улучшает
  связность.

Точка для будущего умного компонента — заменить `ContextBuilder`
движком с тем же входом и выходом (`parts`, `history`, `user_text`,
`memory` → `system`, `messages`, `stats`). Память, сессии и SQLite при
этом не меняются. Включать его стоит флагом в конфиге, со старым
детерминированным путём как фолбэком. Не забыть.
