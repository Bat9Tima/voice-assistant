# Классификатор намерений

Слой между распознанной фразой и общим роутингом. Отвечает на вопрос
«что пользователь делает этой репликой», но ничего не выполняет: команды,
поиск и ответы остаются за `ActionRouter` и `QAService`.

## Зачем

Правила ищут слова, а разговор состоит из контекста. «Мне сейчас получше»
содержит «сейчас», «у меня новое хобби» — «новое», «я прочитал новости» —
«новости». Раньше такие фразы уходили в поиск и возвращали случайную
выдачу вместо ответа собеседника.

Классификатор смотрит на последний вопрос Луны и различает:

- `command` — открыть, включить, громче, поставить;
- `control` — начать или закончить разговор, стоп;
- `answer` — ответ на только что заданный вопрос;
- `dialog` — светская реплика, мнение, рассказ о себе;
- `info` — погода, курс, новости, «сколько стоит»;
- `clarify` — «что ты имеешь в виду», «почему», «подробнее».

Низкая уверенность превращается в `unknown`. В активном режиме это
означает «не запускать поиск вслепую».

## Модель

Используется decisions-эндпоинт ProxyAPI:

```http
POST https://api.proxyapi.ru/v1/decisions
Authorization: Bearer <ключ>
Content-Type: application/json
```

```json
{
  "model": "openai/gpt-6-luna-decisions",
  "state": {
    "dialog_mode": true,
    "awaiting_answer": true,
    "last_luna_question": "Как ты себя чувствуешь?",
    "utterance": "да говорил я такой ну вроде бы сейчас получше стало"
  },
  "questions": {
    "intent": {
      "type": "choice",
      "instructions": "Определи, что пользователь делает одной репликой…",
      "criteria": {
        "command": "Просит выполнить действие…",
        "answer": "Отвечает на вопрос, который Луна только что задала…",
        "dialog": "Поддерживает светскую беседу…",
        "info": "Просит факт, справку или свежие данные…",
        "clarify": "Просит уточнить предыдущий ответ…"
      }
    }
  }
}
```

Ответ содержит вероятности, а не текст:

```json
{
  "answers": {
    "intent": {
      "type": "choice",
      "choice": "answer",
      "confidence": 0.99,
      "probabilities": {"answer": 0.99, "dialog": 0.01}
    }
  },
  "usage": {"input_tokens": 399, "output_tokens": 0}
}
```

Оплачиваются только входные токены. Потокового режима у decisions-моделей
нет. Библиотека OpenAI этот эндпоинт не знает, поэтому запрос идёт обычным
`urllib` с тем же ключом ProxyAPI.

## Состояние разговора

`DialogState` хранит последний вопрос Луны и время, когда он прозвучал.
Вопрос берётся из ответа модели: последнее предложение с `?`. Если ответ
без вопроса, состояние очищается. TTL (`intent.answer_ttl_sec`, по
умолчанию 120 секунд) не даёт старому вопросу влиять на новые реплики.
Вход и выход из разговора состояние сбрасывают.

Состояние живёт только в памяти процесса и не попадает в SQLite.

## Режимы

### shadow

Классификатор считает намерение в фоновом потоке и пишет решение в лог.
Ответ пользователю не задерживается, маршрут не меняется. Это режим по
умолчанию: сначала собираем статистику на реальных фразах.

### active

Перед маршрутом `search` классификатор ждёт решение синхронно (обычно
0,5–1,1 секунды; поиск и так занимает несколько секунд). Если модель
уверенно говорит `answer`, `dialog` или `clarify`, поиск отменяется и
реплика уходит в разговор. `info` и `command` оставляют поиск как был.

Отменяется только `search`. Погода, новости, дата и время, локальные
команды и вход/выход из разговора классификатор не трогает.

### off

Не ходит в сеть и не пишет статистику.

## Ошибки и порог

- HTTP-ошибка, таймаут или битый JSON → источник `fallback`, намерение
  `unknown`. Активный режим оставляет старый маршрут: лучше лишний поиск,
  чем потерянный запрос.
- Уверенность ниже `intent.threshold` → намерение `unknown`, но источник
  остаётся `model`. В активном режиме это повод не запускать поиск.
- Явная просьба поискать («поищи», «погугли», «найди», «посмотри в
  интернете») решается правилом `rules` и в сеть не уходит.

## Настройки

```json
"intent": {
  "enabled": true,
  "mode": "shadow",
  "base_url": "https://api.proxyapi.ru/v1",
  "api_key": "",
  "model": "openai/gpt-6-luna-decisions",
  "threshold": 0.6,
  "timeout_sec": 4.0,
  "answer_ttl_sec": 120
}
```

`api_key` можно не заполнять: при пустом значении берётся
`cloud_llm.api_key`, затем `tts.api_key`.

## Статистика

Каждое решение — одна строка в `logs/assistant.log`:

```
2026-11-17 17:20:01 INFO app.intent_classifier: Намерение [shadow, диалог]:
answer, модель: dialog (уверенность 0.41, model, 0.67 с, токены 396) :: а да нормально
```

Поля: режим, был ли это разговор, итоговое намерение, что предложила
модель до порога, уверенность, источник, время, токены и сама фраза.

Посмотреть распределение:

```powershell
Select-String -Path logs\assistant.log -Pattern 'Намерение \[' |
  ForEach-Object { $_.Line -replace '.*Намерение \[[^]]*\]: (\w+).*', '$1' } |
  Group-Object | Sort-Object Count -Descending
```

Строки с `source = fallback` показывают, как часто сеть или ключ мешают
классификатору. Если их много, активный режим включит старый путь, но
статистика будет неполной.

## Порядок включения

1. `shadow` на несколько реальных разговоров.
2. Проверить, что `answer`/`dialog` уверенно отличаются от `info`.
3. Переключить `mode` в `active`, проверить, что реальные поисковые
   запросы («курс доллара», «какие новости») не отменяются.
4. Отдельно решить, стоит ли отменять новости и погоду. Сейчас они
   остаются на старых правилах.
