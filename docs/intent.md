# Классификатор намерений

Слой между распознанной фразой и общим роутингом. Отвечает на вопрос
«что пользователь делает этой репликой», но ничего не выполняет: команды,
поиск и ответы остаются за `ActionRouter` и `QAService`.

## Зачем

Правила ищут слова, а разговор состоит из контекста. «Мне сейчас получше»
содержит «сейчас», «у меня новое хобби» — «новое», «я прочитал новости» —
«новости». Раньше такие фразы уходили в поиск и возвращали случайную
выдачу вместо ответа собеседника.

Классификатор смотрит на последний вопрос Луны и различает:

- `command` — открыть, включить, громче, поставить;
- `control` — начать или закончить разговор, стоп, сменить манеру речи;
- `answer` — прямой ответ на только что заданный вопрос;
- `dialog` — разговор: приветствие, мнение, чувства, рассказ о себе,
  вопрос о самой Луне, её памяти или внешности;
- `info` — внешние и свежие данные: погода, курс, новости, «сколько стоит»,
  общие знания;
- `clarify` — «что ты имеешь в виду», «почему», «подробнее», «ещё раз».

Главное правило: `answer` — это не «реплика, которую можно счесть
ответом», а прямой ответ по существу. Вопрос, приветствие и новая тема
остаются `dialog`, даже если Луна только что что-то спросила. Вопросы
«что ты помнишь» и «как ты выглядишь» — тоже `dialog`, а не `info`.

Низкая уверенность превращается в `unknown`. В активном режиме это
означает «не запускать инструменты вслепую»: реплика уходит в разговор.

## Модель

Используется decisions-эндпоинт ProxyAPI:

```http
POST https://api.proxyapi.ru/v1/decisions
Authorization: Bearer <ключ>
Content-Type: application/json
```

```json
{
  "model": "openai/gpt-6-luna-decisions",
  "state": {
    "dialog_mode": true,
    "awaiting_answer": true,
    "last_luna_question": "Как ты себя чувствуешь?",
    "utterance": "да говорил я такой ну вроде бы сейчас получше стало"
  },
  "questions": {
    "intent": {
      "type": "choice",
      "instructions": "Определи, что пользователь делает одной репликой…",
      "criteria": {
        "command": "Просит выполнить действие…",
        "control": "Просит управлять самим разговором…",
        "answer": "Прямо отвечает на последний вопрос Луны…",
        "dialog": "Поддерживает разговор…",
        "info": "Просит внешние или свежие данные…",
        "clarify": "Просит повторить или объяснить…"
      }
    }
  }
}
```

Ответ содержит вероятности, а не текст:

```json
{
  "answers": {
    "intent": {
      "type": "choice",
      "choice": "answer",
      "confidence": 0.99,
      "probabilities": {"answer": 0.99, "dialog": 0.01}
    }
  },
  "usage": {"input_tokens": 399, "output_tokens": 0}
}
```

Оплачиваются только входные токены. Потокового режима у decisions-моделей
нет. Библиотека OpenAI этот эндпоинт не знает, поэтому запрос идёт обычным
`urllib` с тем же ключом ProxyAPI.

## Состояние разговора

`DialogState` хранит последний вопрос Луны и время, когда он прозвучал.
Вопрос берётся из ответа модели: последнее предложение с `?`. Если ответ
без вопроса, состояние очищается. TTL (`intent.answer_ttl_sec`, по
умолчанию 120 секунд) не даёт старому вопросу влиять на новые реплики.
Вход и выход из разговора состояние сбрасывают.

Состояние живёт только в памяти процесса и не попадает в SQLite.

## Режимы

### shadow

Классификатор считает намерение в фоновом потоке и пишет решение в лог.
Ответ пользователю не задерживается, маршрут не меняется. Это режим по
умолчанию: сначала собираем статистику на реальных фразах.

### active

Перед маршрутом к внешним данным — `weather`, `news`, `search` —
классификатор ждёт решение синхронно (обычно 0,5–1,5 секунды; сам запрос
всё равно занимает несколько секунд). Если модель уверенно говорит
`answer`, `dialog`, `clarify` или `unknown`, маршрут отменяется и реплика
уходит в разговор. `info` оставляет маршрут как был.

Дата и время решаются локально до классификатора. Уточнения к прошлому
ответу (`followup`, `news_detail`) держатся за контекст и тоже не
отменяются. Локальные команды, вход и выход из разговора классификатор не
трогает: они обрабатываются раньше.

Сетевой сбой — не неопределённость: при `fallback` старый маршрут
остаётся, чтобы погода и новости не пропадали из-за недоступного API.

### off

Не ходит в сеть и не пишет статистику.

## Ошибки и порог

- HTTP-ошибка, таймаут или битый JSON → источник `fallback`, намерение
  `unknown`. Активный режим оставляет старый маршрут: лучше лишний поиск,
  чем потерянный запрос.
- Уверенность ниже `intent.threshold` → намерение `unknown`, но источник
  остаётся `model`. В активном режиме это повод не запускать инструменты.
- Явная просьба поискать («поищи», «погугли», «найди», «посмотри в
  интернете») решается правилом `rules` и в сеть не уходит.

## Распределение

Порядок владельцев реплики:

1. вход/выход из разговора и локальные команды — без классификатора;
2. дата и время — локальный разбор;
3. уточнения к прошлому ответу — по контексту;
4. погода, новости, поиск — правила, но в `active` их может отменить
   классификатор;
5. всё остальное — диалог с основной моделью.

Классификатор не заменяет правила, а стоит перед ними на спорных
маршрутах. Правила отвечают на вопрос «есть ли в фразе тема погоды или
новостей», классификатор — «просит ли человек эту тему или просто
упомянул её».

Примеры:

| Фраза | Маршрут | Почему |
|---|---|---|
| «какие новости» | новости | явная просьба |
| «я прочитал новости» | диалог | утверждение, а не просьба |
| «что последнее ты помнишь» | диалог | вопрос о памяти Луны |
| «какая будет твоя реакция» | диалог | вопрос о Луне, а не поиск |
| «курс доллара» | поиск | короткая просьба-тема |
| «который час» | время | локальный разбор |

Проверка на 40 реальных фразах из лога дала 30 точных попаданий. Ещё
10 — `unknown`; все они разговорные, поэтому уходят в диалог, а не в
инструменты. Ошибочных запусков погоды, новостей или поиска не было.
Единственный `info` ниже порога — «который час» (0.38), но время
считается локально до классификатора.

## Настройки

```json
"intent": {
  "enabled": true,
  "mode": "shadow",
  "base_url": "https://api.proxyapi.ru/v1",
  "api_key": "",
  "model": "openai/gpt-6-luna-decisions",
  "threshold": 0.6,
  "timeout_sec": 4.0,
  "answer_ttl_sec": 120
}
```

`api_key` можно не заполнять: при пустом значении берётся
`cloud_llm.api_key`, затем `tts.api_key`.

## Статистика

Каждое решение — одна строка в `logs/assistant.log`:

```
2026-11-17 17:20:01 INFO app.intent_classifier: Намерение [shadow, диалог]:
answer, модель: dialog (уверенность 0.41, model, 0.67 с, токены 396) :: а да нормально
```

Поля: режим, был ли это разговор, итоговое намерение, что предложила
модель до порога, уверенность, источник, время, токены и сама фраза.

Когда активный классификатор отменяет маршрут, рядом появляется строка:

```
2026-11-17 19:25:49 INFO __main__: Маршрут news отменён: реплика похожа
на разговор (dialog, 0.95)
```

По ней видно, какой именно инструмент не запустился и почему.

Посмотреть распределение:

```powershell
Select-String -Path logs\assistant.log -Pattern 'Намерение \[' |
  ForEach-Object { $_.Line -replace '.*Намерение \[[^]]*\]: (\w+).*', '$1' } |
  Group-Object | Sort-Object Count -Descending
```

Строки с `source = fallback` показывают, как часто сеть или ключ мешают
классификатору. Если их много, активный режим включит старый путь, но
статистика будет неполной.

## Порядок включения

1. `shadow` на несколько реальных разговоров: в лог пишутся решения, но
   маршруты не меняются.
2. Проверить по логу, что `dialog`/`answer` не путаются с `info`, а
   «что последнее ты помнишь» и «какая будет твоя реакция» получают
   `dialog`.
3. Переключить `mode` в `active`. Погода, новости и поиск теперь
   отменяются, если модель уверенно считает реплику разговором.
4. Проверить живьём: «какие новости», «какая погода», «курс доллара»
   должны остаться на своих маршрутах; «что последнее ты помнишь» —
   уйти в диалог.
