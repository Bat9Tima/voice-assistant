# Облачная LLM

Ответы на вопросы, новости и рассуждения идут через ProxyAPI. Локальная
модель в ответах не участвует: она осталась только как опциональный
планировщик команд (`local_planner`).

## Модели

| Роль | Модель | Почему |
|---|---|---|
| Основная | `openai/gpt-6-luna` | хорошо держит русский и JSON v3, отвечает без долгих рассуждений |
| Запасная | `xiaomi/mimo-v2.6-flash` | дешевле, включается при сбое основной |

На пробном резюме GPT-6 Luna с `reasoning_effort: none` дала 3 темы за
3,8 с, простой вопрос — за 2,6 с. Замеры ориентировочные: зависят от сети
и загрузки ProxyAPI.

## Пресеты

Модель переключается одной строкой: `"llm": { "preset": "grok" }`. Пресеты
лежат в `llm_presets` и задают основную модель, модель решений и
`model_params`. Сейчас есть `gpt` (`openai/gpt-6-luna`) и `grok`
(`x-ai/grok-4.3`); у Grok модель решений пока остаётся gpt-ной, потому что
эндпоинт `/v1/decisions` с другими моделями не проверен. Пресет применяется
последним и перекрывает `model` в секциях, поэтому после смены нужен
перезапуск. Эмбеддинги (`memory.model`) и TTS (`tts.model`) пресет не
трогает — это другие модальности.

## Зрение по команде

Команда «посмотри на экран» (и варианты из `vision.triggers`) делает один
снимок основного монитора, сжимает его до 1280 px по ширине (JPEG q75) и
отправляет в `vision.model` через `CloudLLM.answer_image()`. Кадр не
пишется на диск, слежения нет, запасные текстовые модели не подставляются.
Модель зрения отдельная, поэтому переключение чата на Grok её не меняет.

```json
"vision": {
  "enabled": true,
  "model": "openai/gpt-6-luna",
  "max_width": 1280,
  "jpeg_quality": 75,
  "timeout_sec": 60
}
```

Пробник `tools/vision_probe.py` проверяет тот же путь без ассистента:
делает один снимок (без сохранения на диск), сжимает его до 1280 px и
отправляет в выбранную модель. Проверено на `openai/gpt-6-luna`: картинка
доходит, ответ — за ~2,5 с, кадр 1280x720 стоит ~1150 токенов. Запуск:
`python tools/vision_probe.py`; только снимок и кодирование без запроса —
`--dry-run`; вместо экрана можно передать файл через `--image`.

## Поведение

- `CloudLLM.answer()` — единственный метод ответов.
- При ошибке, пустом ответе или таймауте основная модель сменяется запасной.
- Ошибки 429/5xx повторяются (`retries`), 4xx и таймауты сразу уходят к
  запасной модели.
- При недоступности обеих моделей `QAService` возвращает ошибку. Отката на
  локальную модель нет.
- Для рассуждающих моделей используется `max_completion_tokens` с нижним
  порогом 2000: иначе reasoning съедает лимит и ответ приходит пустым.
- `reasoning_effort` задаётся глобально. `cloud_llm.model_params`
  переопределяет поля запроса для конкретной модели; `null` убирает поле.
  GPT-6 Luna принимает только `temperature` по умолчанию и не понимает
  `minimal`, поэтому для неё температура убирается, а режим — `none`.
  Без этого каждый запрос падал бы с HTTP 400.

## Конфиг

```json
"cloud_llm": {
  "enabled": true,
  "base_url": "https://api.proxyapi.ru/v1",
  "api_key": "sk-...",
  "model": "openai/gpt-6-luna",
  "fallback_models": ["xiaomi/mimo-v2.6-flash"],
  "reasoning_effort": "minimal",
  "model_params": {
    "openai/gpt-6-luna": {
      "temperature": null,
      "reasoning_effort": "none"
    }
  },
  "max_completion_tokens": 2000,
  "temperature": 0.2,
  "timeout_sec": 90,
  "retries": 2
}
```

Пустой `api_key` означает «взять `tts.api_key`»: оба сервиса работают через
ProxyAPI.

## Стоимость

Тарифы моделей — в кабинете ProxyAPI. Запасная MiMo дешевле основной и
включается редко.

## Проверка

```powershell
python -m app.doctor
```

Блок «Облачная LLM» показывает адрес, основную и запасную модели и наличие
ключа. Сетевой запрос диагностика не делает, чтобы не тратить деньги.
