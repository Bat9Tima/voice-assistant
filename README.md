# Voice Assistant — локальная «Алиса» на OpenCode

Голосовой ассистент для Windows: слушает микрофон, просыпается по фразе
**«хей луна»**, распознаёт команду локально и выполняет её в браузере.
Быстрые команды обрабатываются детерминированными правилами без LLM,
а агент OpenCode вызывается только явно: «спроси агента …».

```
Микрофон
   │  16 кГц mono
   ▼
Vosk (wake word, офлайн) ──► GigaAM v3 (STT, офлайн)
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
           ActionRouter (правила)        OpenCode agent «voice» (явно)
           YouTube, Google, вкладки,     bin\browser.cmd ... 
           громкость, навигация                 │
                    └──────────────┬──────────────┘
                                   ▼
                     Chrome (CDP + Playwright)
```

## Что уже умеет

- Постоянно слушает микрофон с низкой нагрузкой (Vosk, ~87 МБ модель).
- Активация: «хей луна» (алиас «эй луна») или глобальная горячая клавиша `Ctrl+Alt+Space`.
- Локальное распознавание русской речи (GigaAM v3, CPU, int8) — аудио не уходит в интернет.
- Один движок STT: меньше нагрузка на CPU и память, быстрее запуск и отклик.
- Опционально — английские слова в поисковых запросах (по умолчанию выключено).
- Быстрые команды без LLM: YouTube, Google, сайты, вкладки, навигация, громкость.
- Опционально — свободные фразы через локальную LLM (Ollama/LM Studio): модель
  выбирает действие из белого списка, а исполняет его обычный `ActionRouter`.
  По умолчанию выключено.
- Агент OpenCode по явному вызову «спроси агента …»; незнакомая команда сразу
  получает «Не понял команду», не дожидаясь LLM.
- На время записи команды приглушает Chrome на уровне аудиосессии, чтобы
  музыка не попадала в микрофон; громкость возвращается сразу после захвата.
  Исходная громкость сохраняется на диск, поэтому даже перезапуск ассистента
  во время команды не оставит музыку навсегда тихой.
- Silero VAD (~2 МБ) точнее определяет конец команды; шёпот и очень тихие
  слова по-прежнему ловятся по порогу громкости.
- Управление обычным Chrome через CDP: вкладки, клики, ввод, JS, скриншоты.
- Иконка в трее, уведомления, пауза, лог. Новое уведомление заменяет
  предыдущее, поэтому быстрые команды не создают очередь.
- Автозапуск при входе в Windows.

## Что проверено

Проверка на Windows 11, Python 3.12 и Chrome 156:

- Vosk находит «хей луна» в синтезированной и живой речи.
- GigaAM v3: загрузка ~1,8 с, распознавание 4-секундной фразы ~0,4 с
  (CPU, 4 потока).
- Чистый русский текст распознаётся без английских вставок; при уверенном
  ответе GigaAM (confidence ≥ 0,85) лишний проход Whisper не запускается.
- Полный голосовой цикл: wake word → запись → GigaAM → Chrome. Открываются
  YouTube и видео по запросу.
- Агент OpenCode сам вызвал `bin\browser.cmd`, открыл GitHub и сохранил контекст
  сессии между командами.
- HTTP-мост, `browser.cmd` через демон, иконка в трее, `Ctrl+Alt+Space` и
  установка/удаление автозапуска работают.
- Локальная LLM (`qwen2.5:3b-instruct`, CPU): первый ответ после загрузки
  ~12 с, последующие 1–2 с; корректно разобраны YouTube, SoundCloud,
  системная громкость, вкладки и поиск в Google.

## Требования

- Windows 10/11, микрофон.
- Python 3.12 (не 3.14 — под него пока нет колёс у части ML-библиотек).
- Google Chrome.
- OpenCode Desktop (CLI `opencode-cli.exe` ищется автоматически) и настроенный провайдер.
- Опционально: Ollama и модель `qwen2.5:3b-instruct` (~2 ГБ) для свободных команд.
- ~700 МБ на диске: зависимости, Vosk RU (~87 МБ), GigaAM v3 (~220 МБ).
  Английские модели — опционально, ещё ~140 МБ.

## Установка

Двойной клик по `install.cmd` (или запуск без аргументов) открывает меню:

```
1. Полная установка (эта машина или новая)
2. Обновить исходники из ZIP
3. Только окружение и модели (ремонт)
4. Диагностика
5. Удаление
```

Если Python 3.12 нет, установщик предложит поставить его через winget.
В конце полной установки автоматически запускается диагностика, а весь вывод
дублируется в `logs\install-<дата>.log`.

Для автоматизации те же действия доступны флагами:

```powershell
.\install.cmd -InstallPython          # доустановить Python, если нужно
.\install.cmd -Clean                  # пересоздать .venv
.\install.cmd -DryRun                 # только показать план
.\install.cmd -SourceUrl D:\va.zip    # обновить исходники из архива
```

`install.cmd` вызовет `setup.ps1`, который создаст `.venv`, поставит
зависимости и скачает модели Vosk RU и GigaAM v3, затем настроит автозапуск и
запустит ассистента. Если `config.json` ещё нет, он будет создан из
`config.example.json` — дальше это локальные настройки машины, в git они не
попадают. Модели хранятся в `%LOCALAPPDATA%\VoiceAssistant\models`
(не в папке проекта): Vosk и sherpa-onnx на Windows плохо работают с
кириллицей в путях, а папка проекта может быть названа по-русски.

### Перенос на другой компьютер

1. Скопируйте папку проекта **без** `.venv`, `logs`, `state` (или сделайте
   `git archive -o va.zip HEAD`).
2. На новой машине запустите `install.cmd` — меню само поставит зависимости и
   модели.
3. Для установки **без интернета** заранее сложите архивы моделей в одну папку
   и передайте её установщику:

```powershell
# на машине-доноре: скачать/сохранить архивы (~250 МБ)
.\install.cmd -ModelsDir D:\va-models

# на новой машине: взять готовые архивы оттуда же
.\install.cmd -ModelsDir D:\va-models
```

В `-ModelsDir` сохраняются `vosk-model-small-ru-0.22.zip`,
`vosk-model-small-en-us-0.15.zip` (если ставили английский) и
`gigaam-v3.tar.bz2`. После распаковки установщик сверяет SHA-256 ключевых
файлов моделей, поэтому битый архив не установится молча.

### Синхронизация между ПК (GitHub)

Если ассистент стоит на двух машинах, код удобно держать в одном приватном
репозитории GitHub. Модели, `.venv`, `logs`, `state` и `config.json` в git не
попадают: у каждой машины своё окружение и свои настройки (микрофон, Chrome).

Первичная настройка (один раз):

```powershell
# 1. На github.com создайте пустой приватный репозиторий voice-assistant.
# 2. На основном ПК привяжите его и отправьте код:
git remote add origin https://github.com/<логин>/voice-assistant.git
git push -u origin main --tags

# 3. На втором ПК:
git clone https://github.com/<логин>/voice-assistant.git
cd voice-assistant
.\install.cmd
```

Ежедневная работа:

```powershell
.\sync-pull.cmd   # получить изменения перед работой
.\sync-push.cmd   # отправить свои изменения после работы
```

`sync-push.cmd` сам делает коммит, подтягивает свежие правки и выполняет push.
После `sync-pull.cmd` перезапустите ассистента. Если обе машины правили один
и тот же файл, git сообщит о конфликте — его нужно разобрать вручную.

```
%LOCALAPPDATA%\VoiceAssistant\models\
├── vosk-ru-small\                                  # wake word, ~87 МБ
└── sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16\
    ├── encoder.int8.onnx                           # ~214 МБ
    ├── decoder.onnx
    ├── joiner.onnx
    └── tokens.txt
```

GigaAM v3 — русская ASR-модель от команды GigaChat (MIT). Она заметно точнее
Whisper small на русском и не требует HuggingFace: архив скачивается с GitHub.
По умолчанию это единственный движок распознавания: так меньше нагрузка на CPU
и память и нет лишних задержек.

### Опционально: английские слова в запросах

Английский режим выключен по умолчанию (`"stt": { "parallel_english": false }`).
Он добавляет Vosk EN и Whisper tiny и заметно нагружает слабый CPU, поэтому
включайте его только если действительно нужны английские поисковые запросы.

Модели английского режима, если они уже были скачаны, лежат отдельно:
`%LOCALAPPDATA%\VoiceAssistant\optional-models\` (`vosk-en-small`, `whisper`).
Они не загружаются и не влияют на работу ассистента.

Чтобы включить режим:

```powershell
.\scripts\setup.cmd -English
```

Затем в `config.json` поставьте `"parallel_english": true` и перезапустите
ассистента. Если модели уже лежат в `optional-models`, верните папки
`vosk-en-small` и `whisper` в `%LOCALAPPDATA%\VoiceAssistant\models`.
Отключить обратно: `"parallel_english": false`.

## Первый запуск

```powershell
.\scripts\run.cmd
```

В трее появится иконка. Скажите:

> «Хей луна, открой ютуб»

или нажмите `Ctrl+Alt+Space` и говорите после звукового сигнала.

Проверка без микрофона:

```powershell
.\scripts\run.cmd --text "включи на ютубе лофи хип хоп"
```

### Важно про Chrome

Chrome 136+ не разрешает remote debugging с профилем по умолчанию. Поэтому
ассистент запускает **отдельное окно Chrome** со своим профилем:

```
%LOCALAPPDATA%\VoiceAssistant\chrome-profile
```

При первом запуске войдите в этом окне в YouTube, почту и другие нужные сайты —
это делается один раз. Окно можно свернуть, но не закрывайте его: иначе
ассистент запустит его заново (это займёт пару секунд).

### Аккаунты из обычного Chrome

Chrome 136+ нельзя подключить к профилю по умолчанию, поэтому ассистент не
может работать прямо в вашем текущем окне. Но можно один раз перенести копию
профиля со всеми входами, cookies, паролями, закладками и расширениями:

1. Закройте все окна обычного Chrome.
2. Проверьте план:

   ```powershell
   .\import-profile.cmd -DryRun
   ```

3. Выполните импорт:

   ```powershell
   .\import-profile.cmd
   ```

Скрипт остановит ассистента, сохранит текущий профиль ассистента как
`chrome-profile-backup-<дата-время>` и скопирует выбранный профиль Chrome.
Кэш и история не копируются. После импорта ассистент запустится заново.

По умолчанию берётся профиль `Default` из
`%LOCALAPPDATA%\Google\Chrome\User Data`. Если у вас несколько профилей:

```powershell
.\import-profile.cmd -SourceProfile "Profile 1"
```

Дополнительные параметры:

```powershell
.\import-profile.cmd -NoBackup   # не сохранять старый профиль ассистента
.\import-profile.cmd -NoStart    # не запускать ассистента после импорта
```

Это именно копия на момент импорта: изменения в обычном Chrome после этого не
попадают в профиль ассистента автоматически. Если понадобится — запустите
`import-profile.cmd` ещё раз. Некоторые сайты могут потребовать повторный вход
из-за защиты Chrome; в этом случае войдите один раз в окне ассистента.

## Автозапуск

```powershell
.\scripts\install-autostart.cmd
```

Создаётся ярлык в автозагрузке пользователя — ассистент стартует при входе в
Windows (не до входа в систему). Вариант с Планировщиком задач:

```powershell
.\scripts\install-autostart.cmd -Task   # может потребовать прав администратора
```

Фоновый запуск вручную:

```powershell
.\scripts\start.cmd
```

Удалить только автозапуск и остановить процесс:

```powershell
.\scripts\uninstall-autostart.cmd -Stop
```

## Переустановка и полное удаление

Установщик:

```powershell
.\install.cmd
```

Что делает установщик:

- создаёт `.venv`, если его нет;
- ставит зависимости из `requirements.txt`;
- скачивает Vosk RU и GigaAM v3, если моделей нет;
- настраивает автозапуск;
- запускает ассистента в фоне.

Полезные варианты:

```powershell
.\install.cmd -DryRun              # показать план, ничего не менять
.\install.cmd -Clean               # пересоздать .venv с нуля
.\install.cmd -NoAutostart -NoStart
.\install.cmd -English             # добавить Vosk EN и Whisper tiny
.\install.cmd -English -WhisperModel base  # более точный, но медленный Whisper
```

Если исходники лежат не локально, а в ZIP-архиве, установщик может скачать их:

```powershell
.\install.cmd -SourceUrl "https://github.com/user/repo/archive/refs/heads/main.zip"
```

Подойдёт http(s)-ссылка на ZIP или путь к локальному ZIP. В архиве должен быть
`app\main.py`; папки `app`, `bin`, `.opencode`, `scripts`, `tests` и файлы
зависимостей обновляются. Существующий `config.json` не перезаписывается, чтобы
не потерять ваши настройки. Без `-SourceUrl` установщик берёт исходники из
текущей папки проекта.

Деинсталлятор:

```powershell
.\uninstall.cmd
```

Он останавливает ассистента, закрывает Chrome ассистента, удаляет автозапуск,
`%LOCALAPPDATA%\VoiceAssistant` (модели и профиль Chrome), `.venv`, `logs`,
`state` и кэши. Папка с исходниками и `install.cmd` остаются — по этому же
установщику можно поставить ассистента заново.

Полное удаление вместе с папкой проекта:

```powershell
.\uninstall.cmd -All
```

Перед удалением папки проекта деинсталлятор сохраняет установщик в
`%USERPROFILE%\Downloads\VoiceAssistant-Setup-<дата-время>`. Из этой папки
потом можно запустить `install.cmd` и поставить ассистента заново.

Если нужно удалить вообще всё, без резервной копии установщика:

```powershell
.\uninstall.cmd -All -NoBackup
```

Дополнительно:

```powershell
.\uninstall.cmd -DryRun             # показать, что будет удалено
.\uninstall.cmd -Force              # без подтверждения
```

| «включи видео <запрос>» | то же самое |
| «найди в гугле <запрос>», «загугли <запрос>» | поиск Google |
| «открой вк / почту / гитхаб / кинопоиск / авито» | откроет сайт из списка |
| «открой саундклауд», «включи на саундклауде <трек>» | SoundCloud: поиск и воспроизведение |
| «открой лайкнутые треки на саундклауде» | страница лайков SoundCloud |
| «включи случайный лайкнутый трек на саундклауде» | случайный трек из лайков |
| «включи лайкнутый трек <название> на саундклауде» | выбранный трек из лайков |
| «громкость саундклауда 5», «громкость саундклауда 10» | громкость плеера: 5 = 50%, 10 = 100% |

| «выключи звук в саундклауде», «включи звук на саундклауде» | mute плеера SoundCloud |
| «открой example.com» | откроет любой сайт по домену |
| «открой погоду» (неизвестное название) | ищет в Google и показывает выдачу |
| «открой первую ссылку», «открой ссылку 2» | открывает результат из выдачи Google |
| «пауза», «продолжи», «следующий трек», «предыдущий трек» | управление видео и треками |
| «новая вкладка», «закрой вкладку» | вкладки |
| «переключись на вкладку 2», «какие вкладки» | вкладки |
| «назад», «вперёд», «обнови» | навигация |
| «громкость 5», «громкость пять» | системная громкость: 5 = 50% |
| «громкость 10», «громкость десять» | системная громкость: 10 = 100% |
| «громкость 50», «громкость пятьдесят» | старый формат: 50% |
| «громче», «тише» | системная громкость шагом 10% (1 деление) |
| «громче на 2», «тише на 1», «тише на 20» | изменение на 20% / 10% / 20% |
| «выключи звук», «включи звук» | системная громкость без звука |
| «прокрути вниз», «прокрути вверх», «во весь экран» | страница |
| «что играет», «статус» | текущая вкладка |
| «стоп», «останови видео» | пауза без возврата в начало |
| «перемотай на 30 секунд», «перемотай назад на 10 секунд» | перемотка видео и треков |
| «пауза в саундклауде», «продолжи в саундклауде» | управление именно SoundCloud |
| «следующий трек в саундклауде», «предыдущий трек в саундклауде» | переключение треков SoundCloud |
| «сделай громче», «сделай тише» | громкость по контексту: система или SoundCloud |
| «повтори» | повторить последний поиск или включение |
| «ещё один» | следующий результат последнего поиска |

Громкость задаётся по шкале 0–10: «5» — это 50%, «10» — 100%. Числа
11–100 понимаются как проценты для привычных команд, а «5 процентов» — как 5%.

Агент вызывается только явно — фразой «спроси агента …» (а также
«передай агенту …» или «агент …»). Остальные незнакомые фразы получают
быстрый ответ «Не понял команду» и не запускают агента. Например:

> «Хей луна, спроси агента: найди на авито монитор до десяти тысяч и открой третий результат»

Агент работает через `bin\browser.cmd` и ограничен только этим интерфейсом.

По умолчанию распознаётся только русская речь. Английские названия GigaAM
может передать кириллицей — для YouTube и поиска лучше говорить
по-русски или использовать транслитерацию.

Если английские запросы нужны часто, включите опциональный режим
(`stt.parallel_english: true`) и установите модели командой
`.\scripts\setup.cmd -English`. Тогда в одной фразе можно смешивать языки:

> «Хей луна, найди funny cats»
>
> «Хей луна, включи Bohemian Rhapsody на саундклауде»

Учтите, что этот режим заметно нагружает CPU и увеличивает задержку.

Сайт можно открыть по домену: «открой reddit.com», «открой soundcloud.com».

Если название сайта неизвестно, команда «открой …» покажет выдачу Google.
Скажите «открой первую ссылку», «открой вторую ссылку» или «открой ссылку 3» —
ассистент откроет соответствующий обычный результат и пропустит рекламу.
Если подходящих ссылок нет (капча, только реклама, виджет погоды), страница
поиска останется открытой, а ассистент сообщит об этом.

### SoundCloud

Ассистент работает с плеером SoundCloud отдельно: у него нет обычного тега
`<audio>`, поэтому пауза, следующий/предыдущий трек и громкость нажимаются
через кнопки самого сайта.

- «пауза», «продолжи», «следующий трек», «предыдущий трек» — управление
  текущим треком SoundCloud, если он открыт.
- «громкость саундклауда 5» — 50%, «громкость саундклауда 10» — 100% (та же
  шкала 0–10, что и у системной громкости). «Громче в саундклауде» и «тише на 1
  в саундклауде» меняют громкость плеера на одно деление, то есть на 10%.
  Обычные «громче» и «тише» всегда меняют системную громкость. Если название
  сервиса распознано с ошибкой, но SoundCloud открыт и фраза заканчивается
  числом, ассистент всё равно выставит громкость плеера.
- Ползунок SoundCloud ассистент двигает одним калиброванным кликом: без
  прокрутки туда-обратно. Если клик всё же промахнулся, он повторит его.
- «открой лайкнутые треки на саундклауде» — страница лайков.
- «включи случайный лайкнутый трек на саундклауде» — случайный трек из лайков.
- «включи лайкнутый трек <название> на саундклауде» — поиск по названию среди
  лайкнутых. Ассистент прокручивает список, чтобы подгрузить больше треков.

Для лайков нужен вход в SoundCloud в Chrome ассистента (профиль
`%LOCALAPPDATA%\VoiceAssistant\chrome-profile`). Если сессии нет, ассистент
сообщит, что SoundCloud просит войти. Для обычного поиска и воспроизведения
вход не обязателен: окно входа закрывается автоматически.

### Словарь предметной области

`dictionary.json` в корне проекта хранит варианты названий сервисов. Словарь
дополняет точечные правила для YouTube, SoundCloud и лоуфая и применяется до
разбора команды: «открой гугель» → «открой гугл», «открой в контакте» →
«открой вконтакте».

```json
{
  "version": 1,
  "terms": [
    {
      "id": "google",
      "canonical": "гугл",
      "aliases": ["гугль", {"text": "google", "replace": false}]
    }
  ]
}
```

- `canonical` — к какому написанию приводить текст;
- строки в `aliases` заменяются по умолчанию;
- `{"text": "...", "replace": false}` добавляет вариант для поиска терминов,
  но не меняет текст команды (нужно для неоднозначных слов);
- `"replace": false` на уровне термина отключает замену для всех его алиасов;
- совпадения ищутся по границам слов, самый длинный вариант имеет приоритет.

Если файл отсутствует или содержит ошибку, ассистент работает без словаря и
пишет предупреждение в лог. После правки `dictionary.json` перезапустите
ассистента.

### Интенты и контекст

Быстрые команды описаны в `intents.json`. Интент — это набор шаблонов фраз,
типизированные слоты, действие и приоритет:

```json
{
  "id": "open_site",
  "priority": 60,
  "patterns": ["открой {site}", "open {site}"],
  "slots": {"site": "site"},
  "action": "open_site"
}
```

- `patterns` — фразы; слот пишется отдельным словом, например `{query}`;
- `slots` — тип слота: `site`, `query`, `prefix`, `tab`, `ordinal`,
  `ordinal_word`, `volume`; `prefix` нужен только для ведущего шума перед
  командой («элонорд громкость саундклауда десять»);
- `priority` — чем больше число, тем раньше проверяется интент;
- `requires` — необязательное условие контекста: `search`, `results`, `media`
  или `volume`;
- `action` — что выполнить; действия остаются в `app/actions.py`.

Матчер проверяет интенты по приоритету, приводит слоты к числам и проверяет
значения. Интенты — основной путь: SoundCloud и громкость перенесены в них
полностью. Старый regex-роутер остаётся страховкой для семейств команд, которые
ещё не покрыты шаблонами (YouTube, поиск, сайты, навигация). Единственная
специальная эвристика вне интентов — громкость SoundCloud с потерянным названием
сервиса: если SoundCloud открыт, а фраза заканчивается числом («громкость на
паузу пять»), она считается громкостью плеера. В лог пишется выбранный интент и
слоты:

```
INFO app.actions: Интент: open_site; слоты: {'site': 'ютуб'}
```

Контекст хранится отдельно по видам и живёт `context.ttl_sec` секунд:

- `search` — последний поиск/включение: «ещё один» включает следующий результат,
  «повтори» повторяет запрос;
- `results` — последняя выдача Google: «вторую» открывает вторую ссылку;
- `volume` — куда относилась последняя громкость: после SoundCloud «сделай тише»
  уменьшает плеер, после системной громкости — систему. Голые «тише» и «громче»
  всегда управляют системной громкостью;
- `media` — последнее медиа-действие.

Контекст не перебивает однозначную команду: «громкость пять», «тише» и «громче»
всегда системные, даже если до этого играл SoundCloud. Контекст меняет адресата
только у явных «сделай тише» и «сделай громче». Незнакомая команда и «отмена»
очищают контекст.

### Смена ключевого слова

```json
"wake_aliases": ["привет ассистент", "эй ассистент"]
```

Лучше использовать 2–3 слова, которые редко встречаются в обычной речи.
Vosk-модель остаётся той же — меняется только грамматика распознавания.

Для короткого слова добавьте похожие по звучанию слова в `wake_confusables`:

```json
"wake_word": "луна",
"wake_aliases": ["луна"],
"wake_confusables": ["уна", "она", "лупа", "руна", "дума", "лунь"]
```

Иначе Vosk с грамматикой из одного слова слышит «луна» почти в любом
похожем звуке. Короткие фразы (до 6 символов) сравниваются точно, длинные —
с одной допустимой ошибкой распознавания.

### openWakeWord (экспериментально)

Для фразы «хей луна» можно включить лёгкую модель openWakeWord вместо Vosk:

```json
"wake_word": "хей луна",
"wake_aliases": ["хей луна", "эй луна"],
"wake_engine": "openwakeword",
"wake_model": "hey_loona.onnx",
"wake_threshold": 0.5
```

Модель `hey_loona.onnx` взята из проекта Luna Voice Assistant (лицензия MIT):

```
https://github.com/aachtenberg/luna-voice-assistant
```

Положите файл в `%LOCALAPPDATA%\VoiceAssistant\models\openwakeword\`.

На записях этого проекта openWakeWord оказался заметно хуже Vosk: 6 из 12
всех «хей луна» (4 из 8 на 60 см, 0 из 2 тихих, 0 из 2 с 2 м), при этом
score сильно зависит от фазы потока (один и тот же файл даёт 0.02–0.45).
Vosk с `wake_confusables` на тех же файлах даёт 25 из 26. Поэтому по
умолчанию включён `vosk`.

Если всё же включаете openWakeWord: фразу нужно говорить слитно, без паузы
между словами. «Эй, … луна» с остановкой модель не распознаёт — это одна
непрерывная фраза, а не два отдельных слова. openWakeWord официально
поддерживает только английский, поэтому просто «луна» не сработает. Если
пакет или модель не загрузились, ассистент автоматически вернётся на Vosk.

## Диагностика

```powershell
.\scripts\doctor.cmd
.\scripts\doctor.cmd --record 5 --wake --stt
.\scripts\doctor.cmd --file C:\audio\phrase.wav --wake --stt
```

Вторая команда запишет 5 секунд с микрофона, покажет уровень сигнала, проверит
ключевое слово и распознает текст. Запись сохраняется в
`state\doctor-recording.wav`. Третья проверяет готовый WAV без микрофона
(нужен формат 16 кГц, mono, 16 бит). В выводе есть строка «Рекомендуемый
energy_threshold» — она считается по нижнему процентилю шума, а не по медиане
записи с речью.

Лог: `logs\assistant.log` (открывается из меню трея).

### Оценка wake word и команды

Датасет пишется по `tools\record_dataset\README.md` (план A–O, сессии s1–s7).
Потом:

```powershell
.\.venv\Scripts\python.exe tools\record_dataset\qc.py
.\.venv\Scripts\python.exe tools\wake_eval.py --json results.json
.\.venv\Scripts\python.exe tools\verify_all.py        # wake + команды целиком
```

- `qc.py` проверяет формат и уровни, пишет `qc_report.txt` рядом с датасетом.
- `wake_eval.py` меряет FRR (пропущенные «хей луна») и FAR (ложные
  срабатывания), с разбивкой по блокам, условиям (тишина/вентилятор/музыка/ТВ)
  и дистанции. Ориентир: FRR до ~10% на 2–3 м терпимо, FAR важнее держать
  низким — ложные будят ассистента.
- Руководствуйся решением: если после блоков M/N FAR/FRR не устраивают —
  пора обучать openWakeWord, ориентир 3–5 голосов, 300+ позитивов.

Бэкап датасета (безопасно: только читает, пишет zip в соседнюю папку):

```powershell
.\.venv\Scripts\python.exe tools\backup_dataset.py
```

## Как это устроено

```
app/
├── main.py          конечный автомат: ожидание → слушаю → думаю → ожидание
├── audio.py         захват микрофона, RMS, ресемплинг
├── wake.py          Vosk / openWakeWord — детектор ключевой фразы
├── stt.py           GigaAM v3 (+ опциональный английский режим)
├── actions.py       быстрые команды (без LLM)
├── catalog.py       единый каталог действий: интенты, инструменты, CLI
├── brain.py         запуск `opencode run` и парсинг JSON-событий
├── browser.py       Playwright + CDP, единый поток-владелец
├── browser_cli.py   CLI для агента (демон или прямое подключение)
├── server.py        локальный HTTP-мост 127.0.0.1:8765
├── tray.py          pystray + Windows Toast
└── doctor.py        диагностика
```

Почему отдельный поток для браузера: синхронный Playwright не потокобезопасен,
поэтому все действия идут через очередь в один поток. HTTP-сервер и трей могут
вызывать его из любых потоков.

`catalog.py` — единый список действий: у каждого записаны название, описание,
примеры фраз, интент, инструмент для LLM и команда `browser.cmd`. Из каталога
собирается реестр инструментов и промпт локальной LLM, а тесты проверяют, что
интенты, CLI и таблица команд в README не разошлись с ним.

### OpenCode

Агент описан в `.opencode/agents/voice.md`. У него запрещены файлы и все
shell-команды, кроме `bin\browser.cmd` / `browser_cli`; для свежих данных
(погода, курс, новости) разрешён `webfetch`, чтобы не открывать лишние вкладки.
Модель задаётся в `config.json → opencode.model` (по умолчанию
`opencode/deepseek-v4.1-flash-free`); пустая строка — выбор OpenCode по
умолчанию. Сессия хранится в `state/opencode_session.json`, чтобы работал
контекст «включи ещё одно». При изменении промпта или модели отпечаток
сессии меняется, и агент начинает разговор заново — старые примеры не
перебивают новые правила.

Если CLI не найден автоматически, укажите путь:

```json
"opencode": { "cli": "C:\\путь\\к\\opencode-cli.exe" }
```

### HTTP-мост

Слушает только `127.0.0.1`:

- `GET /status`, `GET /ping`
- `POST /command` `{"text": "открой ютуб"}` — выполнить команду текстом
- `POST /browser` `{"action": "goto", "url": "..."}` — низкоуровневое управление

Пример:

PowerShell 5.1 отправляет кириллицу в теле запроса как `?`, поэтому используйте
UTF-8 явно:

```powershell
$json = '{"text":"включи на ютубе лофи"}'
$body = [System.Text.Encoding]::UTF8.GetBytes($json)
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/command `
  -ContentType "application/json; charset=utf-8" -Body $body
```

Или через `curl.exe`:

```powershell
curl.exe -X POST http://127.0.0.1:8765/command `
  -H "Content-Type: application/json; charset=utf-8" `
  --data-binary "{\"text\":\"включи на ютубе лофи\"}"
```

## Частые проблемы

**Не слышит команду.** Запустите `doctor.cmd --record 5 --wake --stt`, посмотрите
RMS. Если медиана шума близка к порогу — уменьшите `audio.energy_threshold`
до `0.006` или выберите другой микрофон через `input_device`. Также проверьте
Windows: Параметры → Конфиденциальность → Микрофон → «Разрешить классическим
приложениям доступ к микрофону».

**Ключевое слово срабатывает само.** Смените фразу на более редкую, увеличьте
её длину; как запасной вариант — горячая клавиша.

**GigaAM долго думает.** Не увеличивайте `stt.num_threads` вслепую: на
гибридных CPU (P- и E-ядра) больше потоков часто медленнее. Начните с 2–4;
на i5-13420H 2 потока дают ~0.3 с на 3-секундную фразу, а 12 потоков — в
несколько раз дольше. На слабом CPU распознавание 3-секундной фразы занимает
1–3 с.

**GigaAM не загрузилась.** Проверьте, что `scripts\setup.cmd` скачал все четыре
файла модели (см. путь в диагностике). Если архив не докачался, удалите папку
модели и повторите установку.

**Нужен Whisper, а не GigaAM.** Установите `.\scripts\setup.cmd -English` и
поставьте `"stt.engine": "whisper"`. Учтите, что модель Whisper качается с
HuggingFace и может быть недоступна.

**Английские слова не распознаются.** По умолчанию этот режим выключен — так
задумано. Чтобы включить: `.\scripts\setup.cmd -English`, затем
`"parallel_english": true` в `config.json` и перезапуск. Проверьте статус
`stt_english_loaded` и лог «Английское распознавание недоступно». Модели должны
лежать в `%LOCALAPPDATA%\VoiceAssistant\models`: `vosk-en-small` и `whisper`
(после архивации — вернуть из `optional-models`).

**Chrome/CDP не подключается.** Закройте окно Chrome, созданное ассистентом, и
повторите. Порт 9222 должен быть свободен. Если Chrome нестандартно установлен —
пропишите `browser.chrome_path`.

**OpenCode завершился с ошибкой 1.** Текст после «Ошибка:» приходит из события
`error` CLI. Частая причина — `This model is not available in your country`:
укажите рабочую модель в `config.json → opencode.model` (например,
`opencode/deepseek-v4.1-flash-free`) и перезапустите ассистента. Список
доступных моделей: `opencode models`. Быстрые команды работают и без OpenCode.

**Автозапуск не сработал.** Проверьте ярлык в `shell:startup` и
`logs\assistant.log`. Путь к `pythonw.exe` не должен содержать несуществующих
папок после переноса проекта.

**Нет иконки в трее.** Windows 11 по умолчанию прячет новые значки: нажмите
«^» у часов или откройте Параметры → Персонализация → Панель задач → Другие
значки в области уведомлений и включите Voice Assistant. Иконка — серый круг
с микрофоном. После перезапуска Explorer значок может снова уехать в
переполнение — включите его повторно.

Трей самовосстанавливается: watchdog пересоздаёт иконку после сбоя или
зависания (в логе — «Трей запущен», «Трей остановился, перезапускаю»). Состояние
видно в `GET /status` в поле `tray`: `running` — поток иконки жив, `restarts` —
сколько раз watchdog перезапускал её, `error` — текст последней ошибки (`null`,
если ошибки нет). Если `running` равно `false`, а в `error` есть текст, иконку
добавить не удалось.

ВАЖНО: если ассистента запустили не из Проводника (ярлыком), а из терминала,
агента или IDE с ограниченным токеном, Windows может не добавить значок:
`Shell_NotifyIcon(NIM_ADD)` вернёт отказ, в `GET /status` → `tray` появится
`error`, а `restarts` начнёт расти. На некоторых сборках Windows тот же
ограниченный токен давал `WinError 5` на `ChangeWindowMessageFilterEx` — этот
сбой обходится автоматически, но запрет самой Windows обойти нельзя. В таком
случае запускайте через `scripts\start.cmd` или ярлык автозапуска.

Метка Low integrity может стоять и на самой папке проекта — например, после
копирования из песочницы или другого ограниченного окружения. Тогда даже
запуск из Проводника даёт Low-процесс, а вместе с ним — отказ трея и Chrome
без CDP. Проверьте метку: `icacls "<папка проекта>"`. Если в выводе есть
«Низкий обязательный уровень», снимите её и перезапустите ассистента:

```powershell
icacls "<папка проекта>" /setintegritylevel "(OI)(CI)M"
```

**Антивирус ругается.** Разрешите `pythonw.exe` и Chrome. Ассистент не слушает
внешние подключения: HTTP-мост привязан к `127.0.0.1`, аудио не отправляется
в сеть.

## Ограничения текущей версии

- Нет голосового ответа (TTS) — выбрана визуальная обратная связь: уведомления
  и звуковые сигналы.
- Одна команда за раз, без непрерывного диалога.
- Бесплатные модели OpenCode могут быть медленными и иметь лимиты.
- Отдельный профиль Chrome, а не основной.
- Запуск при входе пользователя, а не как служба Windows.
- Английский режим по умолчанию выключен; сложные команды и диалог лучше
  формулировать по-русски. GigaAM может ошибаться на редких именах и названиях.
- Vosk small может ложно срабатывать на похожие фразы; `wake_confusables`
  даёт декодеру альтернативы («хей люда», «эй лужа»), а при частых
  срабатываниях смените `wake_aliases` на более редкую фразу.

## Идеи развития

- TTS: Silero (локально) или Yandex SpeechKit.
- Режим диалога и уточняющих вопросов.
- Больше сайтов и сценариев (Яндекс Музыка, Кинопоиск, Telegram Web).
- Системные команды: приложения, окна, файлы.
- Кастомная wake-word модель — см. раздел ниже.
- Веб-панель управления и история команд.

### Свободные команды через локальную LLM

Незнакомые фразы можно отдавать маленькой локальной модели. Она переводит
фразу в одно действие из белого списка: открыть сайт, YouTube / SoundCloud /
Google, вкладки, навигация, прокрутка, системная громкость, медиа. Модель не
исполняет код и не вызывает shell — она возвращает JSON, который проверяется
по схеме, а выполняет его обычный `ActionRouter`.

Порядок обработки: регексы и контекст → локальная LLM → «Не понял команду».
Явный вызов «спроси агента …» по-прежнему уходит в OpenCode и LLM не трогает.
По умолчанию режим выключен, чтобы на машинах без Ollama ассистент не ждал
недоступный сервер.

Установка (пример с Ollama):

```powershell
winget install Ollama.Ollama
ollama pull qwen2.5:3b-instruct
```

Затем включите в `config.json`:

```json
"llm": {
  "enabled": true,
  "base_url": "http://127.0.0.1:11434/v1",
  "model": "qwen2.5:3b-instruct",
  "timeout_sec": 20,
  "keep_alive": "30m"
}
```

`qwen2.5:3b-instruct` занимает ~2 ГБ и уверенно разбирает короткие команды на
8 ГБ RAM. На машине с 16 ГБ и больше можно взять `qwen2.5:7b-instruct` — она
точнее на длинных фразах, но заметно медленнее на CPU. `keep_alive` оставляет
модель загруженной 30 минут после последнего запроса: первый ответ после
простоя занимает ~10–15 с (загрузка с диска), последующие — 1–2 с. Если
сервер не понимает этот параметр (некоторые сборки LM Studio), поставьте
`"keep_alive": ""`.

Проверка: `python -m app.doctor` покажет блок «Локальная LLM» — адрес, модель
и доступность сервера. Если сервер не отвечает, ассистент не ждёт каждый раз:
первая неудача помечает LLM недоступной на 30 секунд, команда сразу получает
«Не понял команду».

Подойдёт любой OpenAI-совместимый сервер: LM Studio, llama.cpp server и т. п.
Достаточно поменять `base_url` и `model`. Промпт и белый список действий —
в `app/local_llm.py`.

Ограничения:

- модель выбирает только из перечисленных действий; `goto` принимает только
  `http(s)`-адреса, `open_site` — только ключи из `SITE_URLS`;
- сложные сценарии (лайки SoundCloud, «включи мои любимые треки», вопросы)
  остаются за OpenCode;
- небольшие модели путаются на длинных фразах. Отклонённые и неразобранные
  планы пишутся в лог — по ним видно, чего не хватает в промпте или схеме.

### Единый каталог действий (планы)

Чтобы расширение команд не упёрлось в тупик, нужен **единый каталог
действий**: описание, аргументы, примеры и проверка результата. Из него
генерируются регексы/интенты, JSON-схема и промпт для LLM, типизированные
инструменты для OpenCode и документация. Тогда все слои используют один
набор команд и не расходятся.

Что улучшить в инструментах OpenCode:

- сценарные команды с проверкой результата (`play_liked_random`,
  `play_playlist`, `search_and_play`, `set_volume`) вместо цепочек кликов
  по CSS-селекторам;
- `status` с активной вкладкой, сайтом, воспроизведением и громкостью;
- примитивы для незнакомых страниц (`find_by_text`, `click_text`,
  `wait_for`, `snapshot`) вместо сырого `eval`;
- типизированный вызов через MCP/плагин вместо shell-строк;
- ограничить `eval` для голосового агента: содержимое страниц недоверенное.

Масштабирование: при росте числа команд — retrieval top-k и домены/иерархия
вместо всего каталога в одном промпте; сложные многошаговые задачи остаются
за OpenCode. Узкое место — поддержка сценариев и eval, а не размер модели.

Порядок: сначала прогнать 50–100 реальных фраз и разделить ошибки на
«не понял», «понял, но нет действия» и «выполнил не то». Если преобладает
первое — нужен NLU-слой; если второе — сценарные инструменты. Fine-tune —
только если eval покажет меньше 90 % точности.

### Сценарные инструменты агента и маршрутизация (отложено)

Агент OpenCode сейчас работает через низкоуровневые команды `browser.cmd`:
`click`, `fill`, `eval`, `tabs`. Из-за этого он заново собирает то, что
ассистент уже умеет: поиск, включение, паузу, перемотку. Будущая интеграция —
сценарные инструменты с проверкой результата (`search_and_play`,
`play_liked_random`, `set_volume`), богатый `status` (активная вкладка, сайт,
воспроизведение, позиция, громкость) и примитивы страниц (`find_by_text`,
`click_text`, `wait_for`, `snapshot`) вместо сырого `eval`.

Отдельная часть — автоматическая маршрутизация: когда фразу отдавать быстрому
ассистенту, когда агенту, а когда в Q&A. Сейчас агент вызывается только явно
(«спроси агента»), и это осознанно: автоматическое различение требует ещё
одного классификатора и добавляет задержку к незнакомым фразам.

Решение отложено: это отдельный проект, сопоставимый по объёму с обучением
wake-word модели. Каталог действий уже готов принять сценарные записи, когда
до этого дойдут руки.

### Кастомная wake-word модель (отложено)

Цель — заменить Vosk лёгкой моделью, которую можно ставить на другие
устройства: ~1–2 МБ, менее 1% CPU, onnxruntime на Windows, Linux, macOS и
Raspberry Pi. Vosk остаётся запасным вариантом (`wake_engine: "vosk"`).

План:

1. Позитивы — синтез через Piper TTS: 10–20 русских голосов, разные темпы,
   высота и паузы. Свои записи для обучения не нужны.
2. Негативы — 20–50 часов русской речи, музыки и телевизора плюс публичные
   корпуса; отдельно жёсткие негативы «хей люда», «эй лужа», «хей луна-парк».
3. Аугментации — шум, реверберация, громкость, скорость.
4. Обучение — штатный training notebook openWakeWord на GPU (Colab), 2–3
   варианта с разными наборами голосов и аугментаций.
5. Проверка — 30–50 реальных дублей от 2–3 человек и микрофонов, не
   участвовавших в обучении. Метрика — FRR при фиксированном FAR (например,
   одно ложное срабатывание на 10 часов фона), а не точность на синтетике.
6. Сравнение с Vosk в `tools/verify_all.py`, экспорт ONNX и включение через
   `wake_engine: "openwakeword"`.

Важно: чужая модель `hey_loona.onnx` на этом микрофоне дала 6/12 против 25/26
у Vosk. Синтетика ускоряет старт, но решение принимается по отложенным
реальным записям.
